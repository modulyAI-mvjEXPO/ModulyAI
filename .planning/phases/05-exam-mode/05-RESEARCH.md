## Key Design Decision: Response Format

The existing mock `generateResponse()` returns raw HTML strings with `.em-ai-output`, `.em-solution-header`, `.em-marking-scheme`, `.em-step`, `.em-step-title`, `.em-step-num`, `.em-step-content` CSS classes. These are all defined in `ExamMode.css`.

**Options for real AI response format:**

### Option A: AI returns Markdown, frontend converts to HTML
- AI produces standard markdown
- Frontend uses a markdown parser (marked.js or similar) to convert to HTML
- Wraps output in `<div class="em-ai-output"><div class="em-markdown-body">...</div></div>`
- **Pro**: Clean, deterministic rendering; same pattern as StudyMode progressive reveal
- **Con**: Loses the `.em-step`, `.em-step-num` structural elements — answer won't look as polished as mock

### Option B: AI returns structured JSON, frontend builds HTML
- AI returns `{ steps: [...], markingScheme: {...}, tags: [...] }`
- Frontend builds the `.em-step` HTML from the JSON
- **Pro**: Maximum visual fidelity to mock
- **Con**: Complex prompt engineering; JSON hallucination risk; more frontend code

### Option C: AI returns Markdown, wrap in minimal `.em-ai-output` shell
- AI produces markdown
- Wrap in `<div class="em-ai-output"><div class="em-solution-header">...</div><div class="em-markdown-body">...</div></div>`
- A simple header generated by frontend (mark, confidence placeholder)
- **Pro**: Minimal complexity; good visual output; reuses existing CSS
- **Con**: Steps won't have `.em-step-num` numbers — will just be markdown headings

**Decision: Option C** — Markdown from AI, wrapped in a minimal header shell built by the frontend. This is the right balance for a project expo demo:
- Markdown is reliable from any LLM
- The `.em-solution-header` and `.em-marking-scheme` header are easy to build from known data (we know the mark and the question)
- The `em-markdown-body` CSS already styles markdown-like content (h4, ul, p, strong)
- No fragile JSON parsing
- Same pattern used in StudyMode (markdown response rendered in chat)

## Comparison: chat.mts vs exam-solve.mts

| Aspect | chat.mts | exam-solve.mts |
|--------|----------|----------------|
| RAG retrieval | ✅ same | ✅ same |
| System prompt persona | Study assistant | Exam answer writer |
| Mark instructions | MARK_INSTRUCTIONS map | Same map, extended for exam |
| Subject curriculum | SUBJECT_PROFILES | Same |
| History/conversation | ✅ multi-turn | ❌ single-shot (each question independent) |
| Response format | Plain markdown | Markdown answer with VTU formatting emphasis |
| Streaming | False | False |
| Max tokens | 2048 | 3000 (exam answers are longer) |

The exam-solve function is essentially chat.mts with:
1. Different system prompt — exam answer writer, not study assistant
2. No conversation history (each PYQ is independent)
3. Slightly higher max_tokens
4. VTU-specific formatting instruction built into the system prompt

```
You are Moduly AI Exam Engine, a specialized answer-generation system for VTU (Visvesvaraya Technological University) students.

Your task is to generate a complete, exam-ready answer for the given previous year question.

Formatting rules:
- Structure your answer with numbered steps or clear sections
- Use **bold** for key terms and definitions
- Use numbered lists for algorithms or procedures
- For 10M/15M answers: include a brief introduction, full explanation with examples, and a conclusion
- For 5M answers: 1–2 paragraphs with one example
- For 2M answers: 1–3 concise sentences only

- Respond in plain markdown only — no HTML tags
```

## MARKS Discrepancy Note

ExamMode: `['2M', '5M', '10M', '15M']`
StudyMode: `['2M', '5M', '8M', '10M']`

VTU 2024 scheme uses both 8M and 10M. Exam papers typically have 10M and sometimes 15M for Q10 unit questions.

**Decision for Phase 5**: Keep ExamMode's `['2M', '5M', '10M', '15M']` as-is. MARK_INSTRUCTIONS in chat.mts has 2M/5M/8M/10M. The exam-solve.mts will define its own MARK_INSTRUCTIONS with 2M/5M/10M/15M.
