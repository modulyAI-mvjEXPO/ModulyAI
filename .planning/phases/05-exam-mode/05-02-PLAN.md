  <goal>
    Add a "Full Paper" tab to ExamMode that lets the user paste an entire question paper
    (one question per line/block), then generates AI answers for every question sequentially
    and renders a compiled answer sheet. Each question is solved via the existing /exam-solve
    endpoint. No new Netlify function required.
  </goal>

  <design_decisions>
    <decision id="1">
      UI: Add a two-tab toggle at the top of the right (assistant) panel:
        [Single Question]  [Full Paper]
      Single Question tab = existing chat behaviour (already working).
      Full Paper tab = new batch-solve UI in the same panel.
      The left column (upload/analysis) is unchanged for both tabs.
    </decision>
    <decision id="2">
      Full Paper input: a large textarea where the user pastes the full paper text.
      Questions are delimited by blank lines OR numbered patterns like "1.", "1a.", "Q1.".
      A parseQuestions(raw: string): string[] helper splits the input.
      After parse, questions are shown as a numbered list preview before solving.
    </decision>
    <decision id="3">
      Batch solve: clicking "Generate All Answers" calls solveWithAI() for each question
      sequentially (not parallel — avoid rate-limiting the free-tier LLM endpoint).
      Progress indicator: "Solving question 2 of 5..." shown during batch.
      Each solved answer is appended to the answer sheet as it completes.
    </decision>
    <decision id="4">
      Answer sheet rendering: a vertical list of answer blocks, each wrapped in the same
      em-ai-output shell as single-question mode (reuses buildAnswerHtml).
      Each block has a question header: "Q{n}: {question text truncated to 60 chars}".
    </decision>
    <decision id="5">
      Mark selection in full-paper mode: one global mark selector (same MARKS array).
      All questions in the paper are solved at the same mark level. This is a reasonable
      simplification for a demo — real papers have mixed marks but parsing mark per question
      is complex text extraction out of scope.
    </decision>
    <decision id="6">
      State: add paperMode boolean, paperInput string, paperQuestions string[],
      paperAnswers { question: string; html: string }[], batchProgress { current: number; total: number } | null.
      Keep existing single-question message/input state untouched.
    </decision>
    <decision id="7">
      No new CSS file — ExamMode.css already has em-* classes and the new elements
      will reuse existing classes. Any minimal new styles added inline or as em-paper-* variants.
      After inspecting ExamMode.css, we will add a small block of paper-mode specific
      styles at the end of ExamMode.css.
    </decision>
  </design_decisions>

          function parseQuestions(raw: string): string[] {
            // Split on blank lines first
            const blocks = raw.split(/\n\s*\n/).map(b => b.trim()).filter(Boolean);
            if (blocks.length >= 2) return blocks;
            // Fall back: split on numbered patterns (1. / 1a. / Q1. / Q1a.)
            const lines = raw.split('\n');
            const questions: string[] = [];
            let current = '';
            for (const line of lines) {
              if (/^(Q?\d+[a-z]?[.)]\s)/i.test(line.trim()) && current) {
                questions.push(current.trim());
                current = line;
              } else {
                current += (current ? '\n' : '') + line;
              }
            }
            if (current.trim()) questions.push(current.trim());
            return questions.length >= 2 ? questions : blocks.length ? blocks : [raw.trim()];
          }

        ADD solvePaper as a useCallback inside the component:

          const solvePaper = useCallback(async () => {
            const questions = parseQuestions(paperInput);
            if (questions.length === 0 || isTyping) return;
            setPaperQuestions(questions);
            setPaperAnswers([]);
            setBatchProgress({ current: 0, total: questions.length });
            setIsTyping(true);

            const answers: { question: string; html: string }[] = [];
            for (let i = 0; i &lt; questions.length; i++) {
              setBatchProgress({ current: i + 1, total: questions.length });
              try {
                const html = await solveWithAI(questions[i]!, selectedMark);
                answers.push({ question: questions[i]!, html });
              } catch (err: unknown) {
                const errText = err instanceof Error ? err.message : 'Error generating answer';
                answers.push({
                  question: questions[i]!,
                  html: buildAnswerHtml(`**Error:** ${errText}`, selectedMark),
                });
              }
              setPaperAnswers([...answers]);
            }

            setBatchProgress(null);
            setIsTyping(false);
          }, [paperInput, isTyping, selectedMark]);

        NOTE: solveWithAI and buildAnswerHtml are top-level functions already defined —
        they don't need to be in the dependency array (stable references).
        selectedMark and isTyping must be in deps.
