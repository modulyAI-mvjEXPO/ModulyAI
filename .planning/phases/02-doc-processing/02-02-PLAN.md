<objective>
Build the two-function processing pipeline: a synchronous function that creates the document record and immediately returns the documentId, and a background function that downloads the PDF, extracts text, chunks it, embeds each chunk, and stores everything in Supabase.

Purpose: This is the core pipeline that transforms raw uploaded PDFs into searchable vector embeddings. Without it, uploads sit as dead files in S3 with no AI integration. Plan 02-01's utilities (chunker, pdf-extract, types) are composed here into a complete end-to-end flow.
Output: Two Netlify functions (sync + background), updated netlify.toml redirects.
</objective>

  <name>Task 2: Create background processing function</name>
  <files>netlify/functions/process-document-background.mts</files>
  <action>
Create `moduly-ai-landing/netlify/functions/process-document-background.mts` — a Netlify Background Function that performs the end-to-end PDF processing pipeline.

**CRITICAL**: The filename must end with `-background` for Netlify to treat it as a background function (15-min timeout, returns 202 immediately).

The function receives `{ documentId, filePath }` in the request body and:

1. **Parse input**: Extract `documentId` and `filePath` from `event.body`
2. **Initialize clients**: Create Supabase client via `createServerSupabaseClient()`
3. **Create S3 client**: Initialize `S3Client` with Utho credentials (same pattern as `get-upload-url.mjs`)
4. **Download PDF from S3**:
   ```typescript
   import { S3Client, GetObjectCommand } from '@aws-sdk/client-s3';

   const command = new GetObjectCommand({
     Bucket: process.env.UTHO_BUCKET_NAME,
     Key: filePath,
   });
   const response = await s3Client.send(command);
   const bodyBytes = await response.Body?.transformToByteArray();
   if (!bodyBytes) throw new Error('Empty response from S3');
   const pdfBuffer = Buffer.from(bodyBytes);
   ```
5. **Extract text**: Call `extractPdfText(pdfBuffer)`
6. **Check for scanned PDF**: If `result.isScanned` is true (text < 50 chars):
   ```typescript
   await supabase
     .from('documents')
     .update({ status: 'no_text', updated_at: new Date().toISOString() })
     .eq('id', documentId);
   return { statusCode: 200, body: 'no_text' };
   ```
7. **Chunk text**: Call `chunkText(result.text)` with default options (500 chars, 50 overlap)
8. **Embed and store chunks sequentially**:
   ```typescript
   for (const chunk of chunks) {
     const embedding = await getEmbedding(chunk.content);

     await supabase
       .from('document_chunks')
       .insert({
         document_id: documentId,
         content: chunk.content,
         metadata: {
           chunk_index: chunk.chunkIndex,
           page_count: result.pageCount,
         },
         embedding: embedding as unknown as string,
         // pgvector expects the embedding as a string representation
         // Supabase JS client handles the conversion
       });
   }
   ```
   NOTE: Sequential embedding is chosen for simplicity and reliability. Each call takes ~200ms, so 80 chunks = ~16 seconds — well within the 15-min limit.
9. **Update document status to 'ready'**:
   ```typescript
   await supabase
     .from('documents')
     .update({
       status: 'ready',
       chunk_count: chunks.length,
       updated_at: new Date().toISOString(),
     })
     .eq('id', documentId);
   ```
10. **Error handling**: Wrap the entire pipeline in try-catch. On ANY error:
    ```typescript
    console.error(`Document processing failed for ${documentId}:`, error);
    await supabase
      .from('documents')
      .update({
        status: 'failed',
        updated_at: new Date().toISOString(),
      })
      .eq('id', documentId);
    ```
    Return 200 (background functions should always return 200; the status is tracked in the DB).

- `chunkText` from `../../src/lib/ai/chunker`
- `getEmbedding` from `../../src/lib/ai/embedding`
- Use `import type` for type-only imports

- The `@aws-sdk/client-s3` package is already installed (used by `get-upload-url.mjs`)
- Background functions receive the same `event` object as sync functions
- Background functions should return `{ statusCode: 200 }` — the actual status is tracked in the DB
- The embedding array from `getEmbedding()` returns `ReadonlyArray<number>`. Supabase pgvector accepts this directly — no conversion needed.
